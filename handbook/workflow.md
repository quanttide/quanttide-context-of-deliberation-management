# 议事流程

## 概述

议事流程以「议题」为核心，强调从创建到归档的完整闭环，同时允许根据议题类型跳过某些节点（如附议、决议）。

## 五节点生命周期

### 议题创建

- 触发条件：需要集体讨论或决策的任何事项
- 操作：发起人按议题类型选择模板，填写核心元数据（标题、提出人、时间等）
- 输出：带有类型标记的议题草稿

### 动议提出

- 触发条件：议题内容需要明确、可执行的具体提议
- 操作：在「动议区」填写核心内容，随议题类型不同而不同
- 输出：包含完整动议的议题记录

### 附议扩散（可选）

- 触发条件：议题需要其他成员表态、补充意见或表示支持
- 操作：相关人在「附议区」发表意见、补充信息或明确附议

### 决议形成（可选）

- 触发条件：议题经过讨论或评估后，需要做出最终决定
- 操作：在「决议区」记录最终决定、投票结果或结论
- 注意：并非每个议题都会产生决议（如纯澄清或复盘可能只沉淀而不拍板）

### 归档沉淀

- 触发条件：议题已完成动议、附议和决议（如有），内容不再变动
- 操作：将完整议题记录存入议事档案，按年份+周次组织
- 输出：固化的议题标本，确保可追溯

## 议题类型

| 类型 | 动议区核心内容 | 生命周期节点 |
|------|--------------|-------------|
| 议事规则 | 目标、@提及、行动项 | 动议提出 |
| 议程 | 时间、参与者、议程项 | 议题创建 |
| 决策 | 选项列表、决策准则、权衡分析 | 决议形成 |
| 计划 | 目标、里程碑、责任人、时间线 | 决议形成 |
| 复盘研讨 | 问题清单、解决方案、个人心得 | 归档沉淀 |
| 提案审计 | 提案内容 | 决议形成 |
| 澄清评估 | 澄清事项、评估结论 | 附议扩散 |
| 谈判报告 | 谈判对象、过程、结果 | 决议形成 |
| 决议 | 决议内容、投票结果 | 决议形成 |

## 流程特点

- 柔性节点：附议和决议均为可选，实际流程可能只走 1→2→5（如个人复盘）或 1→2→3→5（如需要表态的提案）
- 类型驱动：议题类型决定动议区具体字段，但所有类型共享同一套生命周期节点
- 无辩论区：流程不设开放式讨论环节，偏向动议-附议-决议的简洁路径
