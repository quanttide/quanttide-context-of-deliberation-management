# qtcloud-delib 核心功能规划

> 基于议事档案标本契约 v0.0.2、议事机构章程、议事管理工作手册、议事云产品理念及典型案例整理。

## 一、产品定位

以"议题"为核心的议事管理 SaaS——覆盖"议题创建 → 动议提出 → 附议扩散（可选）→ 决议形成（可选）→ 归档沉淀"五节点完整闭环，按年份+周次组织档案。无辩论区、附议/决议为柔性节点、"模型从资产中长出"（结构由类型模板驱动）。

## 二、领域模型

| 实体 | 要点 | 来源 |
|---|---|---|
| 议题 Issue | 九种类型：议事规则、议程、决策、计划、复盘研讨、提案审计、澄清评估、谈判报告、决议；共享同一生命周期 | contract.yaml |
| 动议区 Motion | 类型驱动的核心字段（决策→选项列表+准则+权衡；计划→目标+里程碑+责任人+时间线；…） | contract.yaml |
| 附议区 Second | 可选；表态、补充、支持 | contract.yaml |
| 决议区 Resolution | 可选；决议内容+投票结果；决策类含"决定"字段 | contract.yaml |
| 会议 Meeting | 时间、参与者、议程项（议程类型议题） | contract.yaml / handbook |
| 档案 Archive | 年份+周次组织；首页含议事活动和编号规则 | contract.yaml |
| 用户/角色 | 议长（主持人）、书记（记录人）、成员；治理层：创始人/上议院/下议院 | bylaw |

## 三、核心功能模块

### 1. 议题管理（MVP）

- 按九种类型模板化创建议题（类型决定动议区字段）
- 动议区/附议区/决议区三区编辑与 Markdown 预览
- 生命周期状态流转：草稿 → 动议 → 附议 → 决议 → 已归档

### 2. 会议与议程管理（MVP）

- 会议创建、议程项可拖拽排序
- 议程项关联议题、@提及行动项（议事规则类型）
- 上次决议执行情况播报、未结事项置顶（周会案例）

### 3. 表决与决议（V1）

- 电子表决：记名/不记名，支持/反对/弃权
- 决议生成：《会议纪要决议案》——做什么/谁负责/何时完成
- 执行跟踪与逾期预警

### 4. 议事档案与归档（MVP）

- 按年份+周次自动归档（契约首页编号规则）
- 档案检索与回溯——"这个决定是怎么来的"
- 档案标本化：可反推验证流程（AI 对照契约检查缺失/多余节点）

### 5. 治理角色与权限（V1，基于章程）

- 创始人：一票否决权（制度兜底，不参与日常议事）
- 上议院/下议院两院流转：标准事项"下议院发起→审议→上议院审议→创始人确认"
- 书记处：整理会议材料、汇总提案、轮值书记
- 三模共存：独立行使 / 两院流转 / 创始人直接行使

### 6. 周会制度支持（V1，手册）

- 周会内容三件套：部门进展汇总 + 决议汇总 + 审计结论
- 周报引用规则约束（只引用已归档档案，不引用原始议事文档）

### 7. 审计管理（V2）

- 会前/会中/会后三段式审计（审计章程）
- 客观评分、偏差转待办、"问题→改进机会"认知框架

### 8. 议事型课堂模式（V2，案例二）

- 课堂项目 + 议题设定 + 学生动议草案
- 轮值议长/秘书、发言队列倒计时投屏
- 过程性评价数据（动议、发言、修正案、投票全记录）

### 9. AI 议事助手（V2，delib-cloud.md 愿景）

- 最小角色模型：议长 / 思考者 / 行动者（IFS 简化）
- 流程：模糊问题 → 议长提炼动议 → 两角色附议 → 冲突判断 → 模拟辩论 → 结构化决议建议 + 未决点清单
- 价值：个人决策"安全外显"、组织沉淀可复用决策逻辑

## 四、实施分期

| 分期 | 模块 | 与现状差距 |
|---|---|---|
| MVP | 议题管理（类型模板）、会议+议程排序、归档 | 小——现有两屏骨架直接演进，补数据模型即可 |
| V1 | 表决与决议、执行跟踪、角色权限、周会模板 | 中——需用户/会议/表决数据模型与权限体系 |
| V2 | 审计、课堂模式、AI 议事助手 | 大——AI 三角色模拟为核心差异化功能 |

## 五、与现有代码的映射

- `issue.dart` 的 `IssueContent`（内容/结论两栏）→ 演进为动议区/决议区双栏编辑器
- `mettings.dart` 的 `ReorderableListView` → 会议议程编排核心组件（50 条占位数据 → 真实议题数据源）
- 需新增：议题类型模板模型、生命周期状态机、归档服务、数据持久化
